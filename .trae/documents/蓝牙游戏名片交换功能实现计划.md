# 蓝牙游戏名片交换功能 —— 实现计划

## Context（为什么做）

用户想做一个开源版的「挂牌」：市面上 tongdiaojihua.com 的硬件挂牌太贵，于是自己实现。
目标行为是——两台装本 App 的手机靠近时，通过蓝牙互相交换「游戏名片」：
游戏名、游戏内 UID、游戏区域（CN / CN_Bilibili / HK / JP / KR / US）。

关键约束：
- 实验性功能，默认关闭；**必须先填好资料才能开启**，在设置页手动打开。
- 自己的资料与收到的名片都存到本 App 的 data 目录，用 JSON 文件。
- 收到的记录保存：获取时间（UTC+8）、对方蓝牙名、以及名片内容。
- 节点标识 = 本机蓝牙名 `RI_PRTS_` + 6 位码（大写字母+数字）。
- 系统范围：Android 5 (API 21) 及以上。
- 节奏：开启后每 **5 分钟**触发一次，每次持续 **3 分钟**，其余时间休眠省电。

已拍板的技术选型：**BLE 广播/扫描做发现 + 经典蓝牙 Insecure RFCOMM 做传输**（混合方案）。

已核实：改蓝牙名只需 `BLUETOOTH_ADMIN`（普通权限，安装即授予），本应用平台签名 + `targetSdk 28`，
**无需 root**；root 路径反而用不上。

## 一、权限与兼容性

### Manifest 新增
```xml
<uses-permission android:name="android.permission.BLUETOOTH"/>
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.WAKE_LOCK"/>
<!-- 防御性：targetSdk 28 下被系统忽略，为将来升 targetSdk 预留 -->
<uses-permission android:name="android.permission.BLUETOOTH_SCAN"
    android:usesPermissionFlags="neverForLocation"/>
<uses-permission android:name="android.permission.BLUETOOTH_ADVERTISE"/>
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT"/>
<uses-feature android:name="android.hardware.bluetooth_le" android:required="false"/>
```

### 兼容性结论
- `BLUETOOTH` / `BLUETOOTH_ADMIN`：全版本 normal，安装即授予。
- BLE 扫描在 API 23+ 需要**运行时** `ACCESS_FINE_LOCATION`，且需开启系统定位服务。
- **targetSdk 28 的红利**：Android 12+ 走 legacy 蓝牙通道，忽略 `BLUETOOTH_SCAN`/`CONNECT`，
  不弹 "Nearby devices" 对话框，运行时段只需那一次定位授权。
- API 16-20：功能判定为"不支持"，开关禁用。所有 BLE 代码用 `SDK_INT >= 21` 硬门禁。

### 运行时申请时机
放在 **SettingsActivity 勾选开关的瞬间**（Service 不能弹权限框）。
申请 `ACCESS_FINE_LOCATION`；授予后再写 prefs 并启动服务。API < 23 直接放行。

## 二、发现机制（BLE）

**31 字节限制处理**：主 ADV 包放 128-bit UUID（不放设备名），SCAN_RSP 包放设备名。

**用掩码 UUID 过滤，不依赖 name 字段**（部分 OEM 不把本地名放进 SCAN_RSP）：
把 6 位节点码编进 UUID 低字节，用掩码匹配前缀。

```java
// b0..b6 = "RI_PRTS" 的 ASCII；b7..b12 = 6 位节点码；b13..b15 = 00
// baseUuid = 52495f50-5254-5300-0000-000000000000
// maskUuid = ffffffff-ffff-ff00-0000-000000000000
ScanFilter filter = new ScanFilter.Builder()
    .setServiceUuid(new ParcelUuid(NodeCode.baseUuid()),
                    new ParcelUuid(NodeCode.MASK_UUID))
    .build();
```

- 广播设置：`ADVERTISE_MODE_LOW_LATENCY`、`setConnectable(false)`（不走 GATT）、`setTimeout(0)`（由 3 分钟窗口控制）。
- 扫描结果处理：从服务 UUID 解析出 `peerCode`；排除自己；`RSSI >= -75` 才算"靠近"；
  从 `ScanResult.getDevice()` 直接取 `BluetoothDevice`（携带协议栈已知地址）用于 RFCOMM。
- 读取 `records.getDeviceName()` 仅用于展示/记录对方蓝牙名。
- 无 BLE 广播能力的机型：降级为"仅扫描"。

## 三、传输协议（Insecure RFCOMM）

- 传输专用固定 SDP UUID：`7a1c9e10-4b3d-4f2a-9c88-2e5b6d7f0a11`（与广播 UUID 区分）。
- 两端都 `listenUsingInsecureRfcommWithServiceRecord("RI_PRTS_CARD", CARD_XFER_UUID)`；
  客户端 `createInsecureRfcommSocketToServiceRecord(...)`，**无需反射** `createInsecureRfcommSocket(channel)`。
- **双向去重规则（对称、两端结果必然一致）**：
  - 我的节点码 `<` 对方 → 我作为 client 主动连；`>` 对方 → 作为 server 等待。
  - 附加 `connecting` / `handledPeers` 集合，窗口结束清空。
- **分帧**：4 字节大端长度前缀 + UTF-8 JSON，上限 8KB。
- **交互时序**：连接建立后双方各自先写自己的名片帧，再读对端一帧，然后关闭（帧极小，不会死锁）。
- **消息体**：
```json
{ "v": 1, "type": "card",
  "node": "A3K9Z2", "name": "RI_PRTS_A3K9Z2",
  "game": "Arknights", "uid": "123456789",
  "region": "CN", "ts": 1759245000 }
```
- **超时**：RFCOMM 无 `SO_TIMEOUT`，用 Handler 看门狗强制 `close()`——connect 8s、读帧 5s。
- 任何 `IOException` → 记日志、关闭 socket、标记该 peer 本轮失败（下轮自动重试）；
  所有 socket `finally { closeQuietly(); }`。
- 窗口结束必须：`stopScan` + `stopAdvertising` + `serverSocket.close()` + 关闭在途 socket。

## 四、调度（新建独立 Service）

**新建 `BluetoothCardService`，不复用 `KeepAliveService`**（后者的职责是悬浮窗保活，混用会导致关不掉 BLE）。
复用同一进程即可共享 KeepAlive 的高存活率。Service 内用 `HandlerThread` + `Handler`。

- `PERIOD_MS = 5min`、`WINDOW_MS = 3min`。
- `startWindow` → 取 `PARTIAL_WAKE_LOCK(窗口+15s)` → `engine.startWindow()` → `postDelayed(stopWindow, WINDOW_MS)`
- `stopWindow` → `engine.stopWindow()` → 释放 wakelock → `postDelayed(startWindow, PERIOD_MS - WINDOW_MS)`
- `onStartCommand`：`startForeground(...)`（API 26+ 建通知渠道）→ 校验 enabled → 恢复上次残留名 →
  保存原始名 → `setName("RI_PRTS_" + code)` → 启动。
- `onDestroy`：清 Handler、`stopWindow`、**恢复原蓝牙名**、释放 wakelock、`stopForeground`。
- **改名/恢复安全**：启用时把当前名写入 `card_prefs.original_bt_name`；停止时仅当当前名以 `RI_PRTS_`
  开头才恢复，避免覆盖用户手改的名字；`original_bt_name` 缺失时回退 `Build.MODEL`。
- 崩溃残留：Service 启动时若发现原始名已存在且当前名是 `RI_PRTS_`，先恢复再重新启用。
- AlarmManager 仅作**可选兜底**（进程被杀后重启），默认不启用。

## 五、存储

全部在 `getFilesDir()`（`/data/data/prts.user.authorization0/files/`）。

- `profile.json` —— 自己的名片（临时资料）。
- `received_cards.json` —— 收到的名片记录。
- `SharedPreferences("card_prefs")` —— `node_code` / `enabled` / `original_bt_name`。

`profile.json`：
```json
{ "version": 1, "game": "Arknights", "uid": "123456789", "region": "CN",
  "node": "A3K9Z2", "name": "RI_PRTS_A3K9Z2", "updated_at": 1759245000 }
```

`received_cards.json`：
```json
{ "version": 1, "cards": [ {
  "received_at": 1759245000,
  "received_at_str": "2026-09-30 21:30:00",
  "peer_node": "B7Q2M4", "peer_name": "RI_PRTS_B7Q2M4",
  "peer_mac": "AA:BB:CC:DD:EE:FF",
  "game": "Arknights", "uid": "987654321", "region": "JP", "proto": 1 } ] }
```

- **时间**：存 UTC epoch 秒（跨时区排序），冗余存 `yyyy-MM-dd HH:mm:ss`（`TimeZone.getTimeZone("GMT+08:00")`）
  便于直接展示。API 16+ 全兼容。
- **并发与原子写**：`CardStore` 统一 `synchronized` 加锁；写盘用「临时文件 → renameTo」避免半写损坏。
- **去重**：`peer_node + uid` 相同则更新 `received_at`，不追加。
- JSON 一律用内置 `org.json`，无第三方依赖。

## 八、实施步骤与验证

1. **权限与清单**：加权限/`uses-feature`/组件声明；`NodeCode`/`Region` 最小实现。
   验证：`.\gradlew assembleDebug` 通过；`adb shell dumpsys package prts.user.authorization0` 见权限条目。
2. **存储层**：`CardProfile`/`ReceivedCard`/`CardStore`/`CardPrefs`。
   验证：debug 包 `adb shell run-as prts.user.authorization0 cat files/profile.json` 看落盘 JSON。
3. **设置页 UI + 资料编辑页**。
   验证：资料未填时开关置灰；填完可用；未填时勾选被拒并 Toast。
4. **调度服务骨架（先不接蓝牙）**：通知 + Handler 调度 + WakeLock + 改名/恢复，仅打日志。
   验证：`adb logcat -s RICard:V` 每 5 分钟一轮；`dumpsys bluetooth_manager` 蓝牙名变 `RI_PRTS_`；关开关后还原。
5. **BLE 广播 + 扫描**：只做发现 + 日志。
   验证：nRF Connect 能看到带节点码的 UUID 与 SCAN_RSP 本地名；两台本 App 设备互打 `peerCode` 与 RSSI。
6. **RFCOMM 传输 + 协议**：服务端/客户端、字典序定向、分帧、看门狗、写记录。
   验证：两台靠近后 `logcat` 出现 `card exchanged`；`run-as ... cat files/received_cards.json` 见双方记录且去重正确。
7. **打磨**：调 RSSI 阈值/超时、清理去重集合、窗口外释放 wakelock、无 BLE 广播降级为仅扫描。
   验证：连续跑 30 分钟无泄漏；关闭开关后无残留 scan/advertise，蓝牙名已还原。

**注意**：模拟器基本不支持经典 RFCOMM，BLE 也需带虚拟蓝牙控制器的镜像。
Step 5-6 必须用**两台真机**验证；模拟器只用于 Step 1-4。

```
adb -s <serial> shell pm grant prts.user.authorization0 android.permission.ACCESS_FINE_LOCATION
adb -s <serial> shell am start -n prts.user.authorization0/prts.user.authorization0.SettingsActivity
adb -s <serial> logcat -s RICard:V
adb -s <serial> shell run-as prts.user.authorization0 cat files/received_cards.json
```
